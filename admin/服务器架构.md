# 栖云野服务器架构与网络配置

> 本页根据仓库中的 `.velocity/velocity.toml`、代理插件配置和三份后端 `server.properties` 整理。端口是当前本机配置，不是玩家连接地址；外部 IP/域名仍以群公告为准。本文不抄录任何口令、转发密钥或数据库凭据。

## 一、拓扑

```text
玩家 → Velocity（0.0.0.0:25565）
		  ├─ sign     127.0.0.1:25564（登录/验证）
		  ├─ lobby1   127.0.0.1:30001（大厅）
		  ├─ survival 127.0.0.1:30101（生存）
		  └─ test     127.0.0.1:30103（代理配置中有登记）
```

`try` 首选后端为 `sign`。代理 `show-max-players=2026` 是服务器列表显示数字，并非硬性人数限制。`ping-passthrough`、query 均关闭。

## 二、后端属性对照

| 属性 | sign | lobby1 | survival |
|---|---:|---:|---:|
| 代理连接端口 | 25564 | 30001 | 30101 |
| 游戏模式 / 难度 | 生存 / 简单 | 生存 / 简单 | 生存 / 困难 |
| max-players | 20 | 20 | 150 |
| view-distance | 10 | 10 | 18 |
| simulation-distance | 10 | 10 | 10 |
| allow-flight | false | false | true |
| online-mode | false | false | false |
| RCON | 关闭 | 关闭 | 开启（25575） |
| query | 关闭 | 关闭 | 关闭 |
| whitelist | 关闭 | 关闭 | 关闭 |
| resource pack required | 否 | 否 | 否 |

三份后端均 `server-ip` 留空，后端自身处于离线认证模式，并配置了 `level-name=world`。玩家认证由代理与 AuthMe 流程组合处理，不要将后端游戏端口直接暴露到公网。

## 三、Velocity 与转发

- 玩家入口监听 `0.0.0.0:25565`。
- `online-mode=false`，Velocity 使用 `player-info-forwarding-mode=MODERN`，密钥从独立 `forwarding.secret` 读取。
- 代理接收 Transfer 连接（`accepts-transfers=true`）；三个后端均不接收 Transfer。
- 代理压缩阈值 256 bytes；解压速率限制约 5 MiB/s；普通数据包 PPS 和压缩字节速率限制未启用。
- `haproxy-protocol=true`：只有当入口前确实有发送 PROXY protocol 的负载均衡器时才应保持开启；直连代理的接入路径需核实。
- 代理地址日志开启。不要在 Wiki、工单或截图中粘贴玩家 IP、密钥或口令。

## 四、登录与跨服

- `AuthMeVelocity` 只将 `sign` 视为认证服，未认证玩家不能跨服，且聊天/命令受限制；登录成功后重定向到 `survival`。
- `sign`、大厅和生存服均安装 AuthMe 组件。代理自动登录转发已启用。
- VelocityReconnect 开启虚拟等待模式，等待端配置 `lobby1`；重连队列关闭。插件当前 server blacklist 中仍是示例服务器名，重连覆盖目标需与实际后端名核对。
- Sonar 在疑似攻击期间验证连接，图形验证码最多 3 次，失败 3 次进入临时黑名单；已设置 Transfer，但目标主机是配置示例值，需确认部署时已替换。
- ViaVersion 对 `sign`、`lobby1`、`survival` 配置了各自协议映射；版本屏蔽列表为空。协议转换不代表所有插件 payload 都跨版本兼容。

## 五、重要安全事项

1. 后端 `online-mode=false` 是代理架构常见设置，但只在后端端口被防火墙限制为代理可达、且 Paper Velocity modern forwarding 正确配置时安全。必须从公网验证 `25564/30001/30101` 不可直连。
2. `survival/server.properties` 开启 RCON；配置文件中存在明文 RCON 凭据。应立刻更换为随机强口令，限制到回环/管理网或关闭 RCON，并确保防火墙不放行公网 25575。本文故意不复述凭据。
3. 仓库中的若干插件配置包含数据库密码/令牌类字段；不要把配置全文提交给公开仓库或复制到 Wiki。凭据若已随仓库分享，应视为已泄露并轮换。
4. `survival` 的 `allow-flight=true` 是兼容插件/飞行能力设置，不等同于向所有玩家开放创造飞行；具体权限仍由插件权限与游戏模式决定。
5. `sign` 和 `lobby1` 的 `max-players=20`、survival 的 150 是后端上限；代理展示的 2026 不覆盖它们。

## 六、代理插件职责

| 插件/配置 | 当前可确认行为 |
|---|---|
| AuthMeVelocity | 登录服隔离、未认证命令和聊天限制、认证后转发至 survival |
| Sonar | 攻击态机器人检测、重力/碰撞/载具检查及按需地图验证码 |
| VelocityReconnect | 后端关闭时等待并尝试自动重连 |
| ViaVersion | 协议转换、代理端包速率限制 |
| SkinsRestorer | 代理与后端均有安装；后端日志提示 Proxy API 模式启用，但未配置共享 SQL 存储，需检查跨服皮肤同步是否实际正常 |
| Simple Voice Chat | 代理配置 UDP 端口 24454；另设公布主机/端口，需与服务器防火墙、客户端可达地址一致 |

## 七、配置维护清单

- 修改后端端口时同步改 `.velocity/velocity.toml` 与防火墙规则。
- 修改 Velocity forwarding secret 时同步更新所有后端 Paper Velocity 配置并完整重启。
- 新增后端需同时核对 `try`、AuthMe 认证规则、ViaVersion server map、重连允许名单/黑名单和插件跨服数据存储。
- `test` 在代理有登记，但不在当前自动登录后端清单/try 顺序中；上线前应确认这是预期配置。
